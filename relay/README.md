# Watch relay (Cloudflare Worker)

Aster does not expose an inbound port. This Worker is the only public piece of the watchers
feature: GitHub posts webhooks to `POST /hook`, the Worker verifies the signature over the raw
bytes, stores each delivery once in D1, and Aster pulls with `GET /pull` using a bearer token and a
sequence cursor. With nothing to return, `/pull` holds the request for up to 50 seconds, so the
application gets near-real-time events without a public endpoint or a busy loop.

Terminal states are also read directly from GitHub by the application's reconcile pass, so a relay
outage delays push deliveries but never loses a merge or a completed run permanently.

## Endpoints

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `POST` | `/hook` | `X-Hub-Signature-256` (HMAC-SHA256, raw body) | Accept a GitHub delivery, dedupe by `X-GitHub-Delivery`, store, answer `202` |
| `GET` | `/pull?after=<seq>&timeout=<s>` | `Authorization: Bearer <RELAY_TOKEN>` | Return at most 500 events with `seq > after`; long-polls up to 50 s |

`/pull` response shape:

```json
{ "seq": 42, "events": [{ "seq": 41, "deliveryId": "...", "event": "pull_request", "payload": { } }] }
```

With no `after`, the response is an immediate baseline: `seq` is the current tail and `events` is
empty. The client persists `seq`; a gap in the sequence resets it and lets the application's
reconcile pass fill the hole.

## Deploy

These steps use placeholders only; never commit a secret value.

1. Install and authenticate Wrangler:

   ```sh
   npx wrangler login
   ```

2. Create the D1 database:

   ```sh
   npx wrangler d1 create aster_watch_relay
   ```

   Copy the printed `database_id` into `wrangler.toml` (it is an identifier, not a secret).

3. Create the table (the Worker also creates it on first use, but doing it explicitly makes a
   failed migration visible before GitHub starts posting):

   ```sh
   npx wrangler d1 execute aster_watch_relay --remote --command \
     "CREATE TABLE IF NOT EXISTS events (seq INTEGER PRIMARY KEY AUTOINCREMENT, delivery_id TEXT NOT NULL UNIQUE, event TEXT NOT NULL, payload TEXT NOT NULL, received_at TEXT NOT NULL)"
   ```

4. Deploy:

   ```sh
   npx wrangler deploy
   ```

5. Set both secrets. Use a random webhook secret generated by GitHub (or generate one yourself) and
   a separate random relay token:

   ```sh
   npx wrangler secret put GITHUB_WEBHOOK_SECRET
   npx wrangler secret put RELAY_TOKEN
   ```

6. In the GitHub repository (or organization) settings, add a webhook:

   - Payload URL: `https://<worker-host>/hook`
   - Content type: `application/json`
   - Secret: the same value as `GITHUB_WEBHOOK_SECRET`
   - Events: `Pull requests`, `Issues`, `Issue comments`, `Workflow runs`, `Check suites`

7. Point Aster at the relay. The integration layer resolves these settings into
   `WatchersConfig`; typical environment names are `WATCHERS_RELAY_URL` (the Worker origin, no
   trailing path), `WATCHERS_RELAY_TOKEN` (the same value as `RELAY_TOKEN`) and
   `WATCHERS_GITHUB_TOKEN` (a read-only token used by reconcile).

## Operational checks

- A `401` from `/hook` means the configured webhook secret does not match; GitHub shows the failed
  delivery, and no payload is stored.
- A `401` from `/pull` means the application's relay token does not match `RELAY_TOKEN`.
- A delivery that GitHub retries is acknowledged with `202` and is not stored twice.
- The Worker writes no logs containing payloads, headers or tokens.

Rotate either secret with `wrangler secret put` and update the matching side (GitHub webhook or
Aster environment) in the same change.

## Limits

- Request body: 1 MiB.
- Pull page: 500 events.
- Long poll: at most 50 seconds per request.
