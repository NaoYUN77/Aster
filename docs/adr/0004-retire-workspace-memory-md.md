# ADR-0004：退役 `workspace/MEMORY.md`，长期事实只走分层记忆

- **状态**：Accepted
- **日期**：2026-10-28（决定见提交 `b59e0cf`；本文件是当时提交信息里预告、此前未入库的记录）
- **决策者**：所有者
- **格式**：MADR 精简版

---

## 上下文

MEM-07 之前，`openAgent` 会在工作目录创建 `workspace/MEMORY.md`，系统提示要求模型在每次请求开始时读取它，并只在用户明确要求记住、纠正或忘记时改写它。分层记忆（working 状态、周期快照、每日归档）接入之后，同一类长期事实有了两条通道。

`memoryDigest` 保持 `null`：B 区不载入这份文件，它只在模型调用文件工具时进入 C 区。把文件摘要放进 facts 会让每一次「记住／忘记」都作废当前周期。

## 决策驱动因素

1. 长期事实只有一个写入面，避免文件工具和记忆工具各写一份。
2. 已有数据目录里的 `MEMORY.md` 不被删除或改写。
3. 不把「文件还在」误写成「应用仍在使用它」。

## 备选方案

### 方案 A：保留 `MEMORY.md` 作为显式长期事实文件

- 优点：和早期 MVP 的验收口径一致（记住的事实出现在该文件里）。
- 缺点：和 working／每日归档并列，模型要在两条通道里选择；文件内容不进 B，快照也不会随它更新。

### 方案 B：停止创建和使用该文件，显式记忆只走记忆工具（采纳）

- 优点：目标、约束和偏好进 working；过去的事实用 `memory_search` 检索每日归档。应用不再创建该文件，提示词不再要求读写它。
- 缺点：早期文档和验收步骤里「检查 `MEMORY.md`」的说法失效，必须改到记忆工具。存量文件留在磁盘上，但不再被使用。

## 决策

采纳方案 B。提交 `b59e0cf`（2026-10-28）已落地：

- `src/agent.ts` 不再打开或创建 `workspace/MEMORY.md`。
- 系统提示改为：用户要求记住、纠正或忘记时使用记忆工具；常驻目标、约束和偏好放在 working memory；过去的事实用 memory search。
- 已存在的文件保留不删。升级用例 `07-E`（`test/memory-integration.test.ts`）断言原内容逐字不变。
- `src/memory/integration.ts` 的 `currentFacts()` 仍返回 `memoryDigest: null`，理由与退役前相同：B 不依赖外部记忆文件的版本。

同一次提交还改了两条提示规则（被问到工具时点名真实工具、Telegram 回复不用 Markdown）。那是提示文本的改动，不是本决策的一部分。提交说明把这两条写成「在生产中观察到的缺口」；仓库里没有配套的脱敏部署记录，本 ADR 不把这句话当作上线证据。

## 后果

- 新会话不会再出现由应用创建的空 `MEMORY.md`。
- 存量文件仍可能留在旧数据目录。应用不读、不写、不迁移它。
- 引用「ADR-0004」的文档以本文件为准。早期设计文里仍出现 `MEMORY.md` 的段落是历史分工，不是当前行为。
