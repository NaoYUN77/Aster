# ADR-0007：投递不承诺恰好一次，未知发送不自动重发

- **状态**：Accepted
- **日期**：2026-10-21

## 上下文

`docs/contracts-and-lifecycle.md` 写明：Telegram `sendMessage` 没有可供本应用使用的幂等键。超时可能发生在 Telegram 已经收到消息之后。分段状态把明确的 4xx 记为 `failed`，把无法排除「已经送达」的传输失败记为 `uncertain`。进程在 `sending` 中被强杀时，恢复后该段也是 `uncertain`。

## 决策

不承诺端到端恰好一次。结果未知的分段不自动重发。操作者停应用后用投递命令核对聊天记录，再选择 `retry`（可能和已送达的内容重复）或 `sent`（该段视为已送达，继续后面的分段）。这两条命令只改本地投递状态，不重新执行 agent。

## 备选方案

- **超时后自动重发整条或该段。** 契约写明不能保证这样不会重复。仓库没有记录自动重发的流量或费用。
- **把未知发送当成未发送并立刻再跑 agent。** 同一节写明回复已保存后应从投递记录发送，不重新执行任务。自动重跑会把未知副作用当成没发生。

## 后果

- 可能漏掉一条用户其实没看到的消息，直到有人核对并 `retry`。
- `retry` 可能造成重复回复。部署指南把这写成预期风险。
- 投递失败不会把已经完成的 agent 任务再跑一遍。
