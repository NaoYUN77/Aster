# ADR-0014：工具由人注册，模型不能在运行时自注册

- **状态**：Accepted
- **日期**：2026-10-22

## 上下文

`docs/tool-registration-research.md`（2026-10-22）比较了若干 personal agent 和 MCP 的做法，结论是：主流产品不让模型在运行时自由注册可执行工具。注册和授权由人完成，模型只发现并调用已有工具。该文同时写明，当前实现是代码里的 `defineTool` 加上启动时安装。MCP 配置文件后来让人可以不改代码就接入 server，但配置仍然是人写的。

## 决策

模型不能注册新的可执行工具。内置工具在代码里登记。MCP server 来自 `mcp.json`（或 `MCP_CONFIG`），由所有者配置。名称冲突在注册时拒绝。

## 备选方案

- **让模型写工具并在下次请求加载。** 调研记录把这类做法放在研究型 agent，并写明需要沙箱和人工审核，不是这里的默认。仓库没有记录沙箱方案的费用。
- **每加一个私有集成都改代码再部署。** 同一篇调研把这写成当时的问题，并建议私有集成走独立进程或 MCP，而不是模型自注册。MCP 接入已经落地，见 `docs/mcp.md`。没有记录「改代码部署」比 MCP 贵多少。

## 后果

- 新能力要么改代码，要么改 MCP 配置后重启。模型不能在对话里安装工具。
- 工具描述仍会进入模型上下文。调研记录把投毒风险留在集成侧，本篇不把它收成已实现的过滤。
- 写操作的二次确认不在本期。ADR-0003（[PR #28](https://github.com/NaoYUN77/Aster/pull/28)）把 authz 复核收进 v0.1，默认 write、不采信远端 annotations。那是授权，不是模型自注册。
