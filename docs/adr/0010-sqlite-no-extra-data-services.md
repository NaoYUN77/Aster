# ADR-0010：状态放在 Node 内置 SQLite，不另起数据库或向量服务

- **状态**：Accepted
- **日期**：2026-10-21

阅读说明（2026-10-30）：下文对旧 MVP 排除项的引用只描述决策背景；产品范围现见 [当前目标与开放范围](../mvp.md)。记忆检索增强可以立项；本篇不部署独立数据服务的取舍仍有效，如需改变则记录后继 ADR。

## 上下文

`CLAUDE.md` 的部署基线是单台 4 核 CPU、4 GB 内存，模型推理在远端。`docs/mvp.md` 写明：底座用 Node 内置 SQLite 保存会话和执行状态，接入与投递用另一个 SQLite 文件，不需要数据库服务。`docs/memory-and-context-design.md` 写明本轮不包含向量数据库、第二套 agent loop 和磁盘历史清理。`docs/mvp.md` 把 PREFERENCE 和向量检索放在本次范围之外。

## 决策

持久状态使用进程内的 `node:sqlite`（`agent.sqlite` 与 `inbox.sqlite`）。记忆的每日事实是 `memory/daily/*.md`，检索不是向量索引。不部署独立数据库、缓存或向量库。

## 备选方案

- **单独的数据库服务或消息队列。** `docs/contracts-and-lifecycle.md` 的实现尺度写的是不需要额外消息队列。仓库没有记录托管数据库的价格。
- **向量检索记忆或工具。** 工具检索的取舍见 [ADR-0002](0002-tool-search-bm25-before-semantic.md)，本篇不重复。记忆侧只记录「本轮不做向量库」。没有嵌入模型的费用或内存实测写在决策当时的文档里。后来的记忆验收记录了 faux 负载下约 136 MiB 的 RSS，那是机制测量，不是向量方案的对比。

## 后果

- 部署更新必须保留数据目录。没有单独的数据库可以迁移。
- 关键词检索对不上时，没有向量召回可以兜底。
- 两个 SQLite 文件加上 WAL，备份按整卷做，不把会话和投递拆进不同的服务。
