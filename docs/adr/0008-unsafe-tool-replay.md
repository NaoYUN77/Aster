# ADR-0008：外部工具调用按不可重放处理

- **状态**：Accepted
- **日期**：2026-10-21

## 上下文

`docs/contracts-and-lifecycle.md` 记录 pi-durable 1.3.0 的行为：默认 `replay` 是 `unsafe`。只有持久化策略和当前工具策略都是 `safe` 时，已保存的执行意图才会重跑。MCP 工具在 `docs/mcp.md` 和契约里一律标成 `replay: "unsafe"`。工具体系范围见尚未合并的 [PR #28](https://github.com/NaoYUN77/Aster/pull/28) 中的 ADR-0003；本篇只记录重放策略本身。

## 决策

MCP 调用不在进程中断后自动重跑。恢复时如果结果未知，按底座规则报告未知，不因为后来的权限或健康状态变化再执行一次。内置 `current_time` 在代码里标成 `safe`；文件和 bash 工具沿用底座策略。

## 备选方案

- **把 MCP 标成 safe，中断后重放。** 文档写的理由是避免重复外部副作用。仓库没有记录某次重复调用的具体损失金额。
- **由应用自己做一套重放队列。** 契约要求复用底座策略，不另建一套。没有比较实现成本的数字。

## 后果

- 中断后的外部写操作可能已经生效，也可能没有。恢复不会靠再调用一次来「补齐」。
- 安全重放的工具仍会再执行。把有副作用的工具标成 `safe` 会打破这条边界。
