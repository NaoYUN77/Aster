# ADR-0019：PTC 代码调用工具（codemode）

- **状态**：Accepted
- **日期**：2026-11-02
- **功能**：codemode-ptc

## 上下文

PTC／Code Mode／CodeAct 的共同做法是：模型写一段程序，由宿主执行其中的工具调用，只有程序结果回到模型上下文，中间结果不进入对话。需要验证的三点是：脚本能运行、脚本中的工具调用经过代理、只有最终结果进入模型上下文。

本仓库以 pi-durable 1.3.0 为 agent 底座，不另建模型循环。该版本已提供 `@earendil-works/pi-durable/codemode`：`codemode` 工具在 QuickJS WASM worker 中执行模型写的 JavaScript，脚本只能看到注入的工具、输出助手、`store`／`load` 和工具发现函数，没有文件系统、网络、计时器或模块加载。脚本按确定性日志重放，嵌套工具调用不进入对话记录。

项目同时支持本地执行与远程执行（[ADR-0021](../0021-control-execution-split.md)）。远程执行阶段 1 只有 `bash`；`read`／`write`／`edit` 等文件工具返回 `not_supported`。既有约束还包括：同一回合工具顺序执行（[ADR-0009](../0009-sequential-tool-execution.md)）、工具执行前统一复核名称／状态／权限、模型可见输出有上限，以及不安全工具不自动重放（[ADR-0008](../0008-unsafe-tool-replay.md)）。

## 决策驱动因素

- 复用底座循环、工具校验、持久化与恢复，不引入第二套执行框架。
- 中间工具结果不进入模型上下文，脚本结果必须有明确上限。
- 嵌套调用仍经过应用注册表、参数 schema 和宿主授权；脚本不能自行提升权限。
- 远程执行阶段 1 没有远程文件 API，不能让脚本以为文件工具可用。
- 资源、并发、超时和关闭有边界；恢复语义与既有工具策略一致。

## 备选方案

- **自建 Node `vm` 或 Python 子进程执行器**：需要另做沙箱、工具桥、输出截断和恢复；与底座已有的 codemode 重复，也更容易把宿主能力暴露给脚本。不采用。
- **默认开启**：会改变所有部署的工具声明和系统提示，并把一条新的写执行路径无条件暴露给模型。采用显式 `CODEMODE_ENABLED=1`。
- **脚本可调用全部已注册工具**：远程模式下文件工具不可用，MCP 工具是延迟加载且输出上限另有一套，脚本面过大。v1 只开放文件／命令工具，MCP、记忆和 Web 工具留给模型直接调用。
- **把 codemode 的完整输出自动写到控制面临时文件**：本地模式可行；远程模式下模型的文件工具在执行主机上，读不到控制面的路径。更可靠的做法是让脚本把大输出用 `bash` 写到执行主机，再由后续 `bash` 读取。
- **允许脚本并发调用工具**：与 ADR-0009 的顺序执行边界冲突，也会放大共享状态竞争。v1 在宿主侧把嵌套调用串行化；`Promise.all` 仍可用，但实际一次只运行一个调用。
- **让脚本调用 `codemode` 自身**：会造成脚本嵌套脚本，没有相应的边界和配额。保留底座默认的 `callers: ["model"]`。

## 决策

启用 `CODEMODE_ENABLED=1` 后，`openAgent()` 安装底座的 `codemode` tool：

- 使用 `CodemodeSandbox`（QuickJS WASM，每次执行一个 worker 线程）和 `createCodemodeExtension({ sandbox, models: false })`；不启用底座额外的模型工具。
- 工具只允许模型调用；脚本不能递归启动 codemode。
- 脚本可调用的工具由宿主白名单限制，并通过工具的 `callers` 属性实现：本地模式为 `read`、`write`、`edit`、`bash`；远程模式只有 `bash`。模型仍然能看到全部工具；白名单只影响 `agent.callable` 进入脚本的部分。
- 模型可见结果上限为 32 KiB／1000 行，保留尾部；覆盖底座默认的 4 MiB／100000 行。脚本仍可用首行 `// @options` 设置 `max_output_tokens` 和 `timeout_ms`，但最终仍受此上限和任务超时约束。
- 嵌套调用串行执行；codemode 调用结束（完成、失败或超时）或被取消时，仍在运行的嵌套调用被取消，尚未开始的排队调用不再启动。
- 默认脚本期限 240 秒、QuickJS 内存上限 128 MiB；配置范围分别为 1–300 秒和 16–512 MiB。`openAgent()` 关闭时关闭 sandbox。
- 远程模式下脚本只看到 `bash`；大输出由脚本写入执行主机文件，后续用 `bash` 读取。控制面不承诺自动保存完整脚本输出。
- 不把 MCP、记忆、Web 工具放进 v1 脚本面，也不把执行主机加入控制面网络。

## 后果

- 新增直接依赖 `@earendil-works/pi-codemode` 1.3.0；运行期增加一个 QuickJS worker 线程及 WASM 内存，单次 codemode 调用完成后 worker 退出。
- 模型上下文只收到脚本结果；脚本源码本身仍是工具参数，会进入 durable 会话记录，因此不要把秘密写进脚本或命令参数。
- 输出被双重限制：脚本自身的 token 预算和宿主的 32 KiB／1000 行上限。远程模式的自动完整输出落盘不可用，只能看到截断提示；大输出必须落到执行主机。
- v1 不提供脚本并发、脚本内 MCP／Web／记忆工具、脚本递归或 OS 级隔离。`bash` 仍不是安全沙箱；QuickJS 只限制脚本运行时能力，不限制命令本身。
- 恢复遵循底座：codemode 声明为安全重放，已完成的嵌套结果从日志恢复；`bash` 是 unsafe，崩溃时未完成的嵌套调用不会被自动重跑，按结果未知／未完成处理。

## 分阶段决策与缺陷历史

### 2026-11-02：首次实现

- 相关 spec：`docs/spec-20261102-codemode-ptc.md`（历史文件名；本功能完成后已删除）
- 决策与取舍：采用底座 codemode，启用方式为显式环境变量；脚本工具白名单按本地／远程执行模式区分；嵌套调用串行化以保持 ADR-0009；远程模式不假装支持自动输出落盘。
- 相关缺陷：底座 codemode 的脚本超时只终止 VM，传给嵌套工具的仍是请求级上下文，不会因脚本超时中止正在运行的 I/O。宿主包装层在 codemode 调用结束时中止嵌套上下文，并阻止排队调用启动；验证见 `test/codemode.test.ts` 的 "nested calls stop when their script call ends"。
