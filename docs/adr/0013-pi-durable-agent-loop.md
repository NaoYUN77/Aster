# ADR-0013：agent loop 只用 pi-durable，应用不再写一套

- **状态**：Accepted
- **日期**：2026-10-21

## 上下文

`CLAUDE.md` 规定本项目以 pi-durable 为底座，复用它的 agent loop、工具执行和持久化。模型调用通过底座接入。应用层不另建一套 agent loop。版本固定为已安装的 1.3.0，不照搬上游主分支里还没发布的接口。`docs/memory-and-context-design.md` 把「第二套 agent loop」列在本轮不做的清单里。

## 决策

会话、工具调用和执行恢复使用 pi-durable 的 Session 与 SQLite 存储。应用负责 Telegram、记忆组装、工具注册和投递，不自己实现模型循环。

## 备选方案

- **在应用里再写一个循环，只把 pi-durable 当存储。** 仓库级约束明确否定这条。没有记录自研循环的工期或费用。
- **换另一个 agent 框架。** 现有文档没有第二份框架的对比表或价格。

## 后果

- 恢复语义、工具重放和压缩以 1.3.0 的已核实行为为准，写在 `docs/contracts-and-lifecycle.md`。升级底座要先对未完成调用做兼容。
- 记忆和投递不能另造一份底座状态。展示用的回复文本不能拆掉工具调用关联。
- 底座没公开的能力（例如 MCP 连接关闭后的自动重连）不能靠猜上游主分支来补。
