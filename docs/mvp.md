# Personal Agent MVP

## 项目目的

基于 pi durable 构建部署在个人云服务器上的 personal agent。通过 Telegram 发送请求，由底座执行 agent loop 和工具调用，最终将结果返回 Telegram。交互直接、清晰，不设计情感人格；未来可根据用户明确表达的偏好调整行为。

部署资源为 4 核 CPU、4 GB 内存。模型推理由远端 API 提供，本机承载应用、底座状态和工具执行。

本文件记录当前 MVP 的范围和设计，具体功能决策不写入仓库级 CLAUDE.md。

后续的三块上下文、working memory 和每日记忆归档见 [Memory 与 Context 实施方案](memory-and-context-design.md)，任务拆分见 [实施 issues](memory-implementation-issues.md)。这些能力尚未接入运行中的 agent；MEM-01 冻结了数据契约，MEM-02 实现了 Working Module 与原生工具，MEM-03 实现了纯 Context 规划与快照渲染，但均未在组合入口注册。本文仍描述当前 MVP。

## 当前范围

- 单用户、Telegram 私聊、文本消息。
- Telegram 长轮询接入，不要求对公网开放 webhook。
- pi durable 提供 agent loop、会话状态及恢复能力；按底座接口接入文件读写和编辑工具。
- 自定义工具通过代码显式注册，使用底座兼容的参数 schema，执行前完成参数校验。
- 长期记忆先存放在一个 Markdown 文件中；读取和修改复用文件工具。
- 同一会话依次处理请求。初始全局 agent 并发为 1，避免消息交错和共享文件并发写入。
- 只将最终可展示文本发送给用户，长回复由 Telegram 适配层分段。

## 数据边界

处理链路：Telegram update → 内部文本请求 → pi durable 会话 → 内部回复 → Telegram sendMessage。

- Telegram 适配层负责身份及私聊校验、update/message/chat 标识转换、文本提取与发送限制。
- 内部请求使用稳定的请求标识、会话标识、发送者标识和文本。身份由接入层确定，不能由模型工具参数冒充。
- 底座适配层负责内部请求与 pi 消息/运行接口之间的转换，并保留底座完整的会话与工具调用记录。
- 工具边界负责模型参数校验、外部服务格式转换，以及错误向底座工具结果的映射。
- 最终回复投影为文本不代表会话记录也只能保留文本。

## 记忆与运行状态

长期记忆与会话历史是不同的数据：长期记忆存放在独立文件，会话和恢复状态使用底座自身机制。不能用一个记忆文件替代执行日志。

长期记忆仅保存用户要求记住的事实，不把每条聊天自动追加为记忆。没有记忆文件时按空记忆处理；其他读取失败必须显式报告。偏好文件 PREFERENCE、自动偏好提取、向量检索及复杂记忆分层不在本次范围。

运行目录必须持久化。底座使用 Node 内置 SQLite 保存会话和执行状态，接入与投递使用独立 SQLite 文件；无需数据库服务。部署更新不能覆盖记忆、会话和消息处理状态。

## 工具契约

具体参数、结果、重放与请求生命周期设计见 [contracts-and-lifecycle.md](contracts-and-lifecycle.md)，通用规则见 [CLAUDE.md](../CLAUDE.md)。MVP 通过代码注册自定义工具，使用 `current_time` 验证扩展路径；文件读写、编辑和 bash 复用底座工具。

## 资源与部署

- 单机、单应用进程，Node.js 24.19.0；Linux 部署示例通过 systemd 与 flock 托管。
- 不在 4 GB 服务器上运行本地大模型；暂不引入向量数据库或独立缓存服务。
- 为输入大小、工具输出、执行时长和待处理请求设置明确上限；不能静默截断用户输入。
- 使用独立的运行工作目录；Telegram token 和模型凭据通过部署环境注入，不写入仓库或日志。
- 使用进程管理器托管应用并优雅退出。云服务器操作系统和底座兼容性需在部署前核实。

## 验收

1. 配置凭据后，授权用户可从 Telegram 发送文本并收到 agent 回复。
2. 连续两条消息共享会话上下文；并发到达时保持顺序。
3. 一个自定义工具可被注册、被 agent 调用并返回结果；非法参数不能触发执行。
4. 用户要求记住的内容写入记忆文件，重启后仍可读取。
5. 非授权用户的请求不触发模型或工具执行。
6. 模型失败、工具失败和 Telegram 发送失败有可区分的诊断信息。
7. 使用真实底座验证重启与恢复行为，并记录尚未覆盖的交付窗口。
