# Aster 当前目标与开放范围

更新日期：2026-10-30。本文是产品目标与功能演进范围的权威入口，保留 `mvp.md` 路径以兼容既有链接。早期 MVP 已作为起步阶段结束；旧清单中的排除项不再构成功能开发禁令。

## 当前目标

Aster 是长期运行的个人 AI agent，以 Telegram 为当前入口，以 pi-durable 承担 agent loop、工具执行和恢复，通过长期记忆保持任务连续性，并通过内置工具和 MCP 连接外部能力。

开发围绕实际个人使用需求推进：让 agent 更好地理解和执行任务、利用记忆、接入个人服务，并在明确授权下提供主动服务。每项功能按具体任务定义设计、实现与验收，不要求继续维持早期 MVP 的功能清单。

## 当前已实现的基础

以下是现有实现的起点，具体配置与限制以 [README](../README.md)、工具 schema 和对应契约为准。

- Telegram 单 owner 私聊文本接入，长轮询收件；当前单会话、串行请求与顺序工具执行。
- pi-durable 原生会话、工具调用、持久化 checkpoint 与中断恢复；接收、执行和投递分别保存状态。
- 分层记忆：working 任务与明确偏好、周期快照、近期原文、每日事件归档及有界检索。`workspace/MEMORY.md` 已退役，见 [ADR-0004](adr/0004-retire-workspace-memory-md.md)。
- 文件与命令工具、自定义工具注册、MCP 接入和按需发现；外部工具注册与授权由宿主管理。
- 单服务 Docker 部署，持久化数据与代码分离。生产运行情况与已有验证证据见 [README](../README.md#已验证与尚未验证)，部署操作见 [部署指南](deployment-test-guide.md)。

现有能力不等于所有场景均已验收。缺少某项生产证据应标记为未覆盖，不据此推断项目从未部署，也不把旧验收中的阻塞当作当前事实。

## 已开放的功能方向

下表解除早期 MVP 的统一排除限制，表示这些方向可以立项、设计和实现；它不是已经交付的能力清单，也不规定开发顺序。

| 方向 | 开放范围 | 实施时需要明确的边界 |
| --- | --- | --- |
| 计划任务与主动服务 | 定时提醒、周期任务、条件触发和主动推送 | 用户授权、时区、任务持久化、取消、重复执行及投递语义 |
| 多模态与交互 | 图片、语音、附件、富文本和其他 Telegram 交互 | 协议转换、模型支持、输入输出大小、文件保留与费用 |
| 记忆增强 | 更好的检索、纠正与删除、偏好管理、历史保留与清理 | 数据归属、来源证据、撤销语义、隐私与迁移；是否采用语义或向量检索按需求评估 |
| 工具与个人集成 | 新内置工具、MCP 服务、工具管理体验及受控扩展机制 | 宿主注册与授权、凭据隔离、schema 兼容、超时与副作用；现行注册决策见 [ADR-0014](adr/0014-humans-register-tools.md) |
| 多会话与并发 | 任务或话题隔离、多个会话、按需要调整并发 | 状态隔离、单写者或并发控制、资源预算及消息顺序 |
| 入口与用户模型 | 其他渠道、群组交互；有明确需求时评估多用户支持 | 身份认证、会话路由、记忆隔离及各渠道投递契约；个人使用仍是当前产品重心 |
| 行为与个性化 | system prompt、沟通风格、用户明确选择的个性化或人格表达 | 准确陈述能力、偏好来源与适用范围、用户可更正和撤销 |

不再将 PREFERENCE 文件、单文件记忆或某种插件布局作为预设交付要求。根据实际能力选择数据模型和接口；已经退役的实现也不因范围开放而自动恢复。

## 继续适用的工程约束

功能范围开放后，仓库级工程约束仍以 [CLAUDE.md](../CLAUDE.md) 为准：复用 pi-durable、在边界验证和转换数据、保持持久化兼容、保护凭据，并满足单台 4 核 CPU／4 GB 内存的部署基线。当前模型推理由远端提供。

身份校验、执行恢复、投递恢复与外部副作用语义应在实现中保证。新功能不能仅通过提示词宣称具备隔离、强制审批或恰好一次执行。

现行架构取舍见 [ADR 索引](adr/README.md)。功能扩展涉及改变某项已接受决策时，记录新的取舍并更新关联契约；未触及决策的功能可以直接增量实现，无需先修改旧 MVP。

## 新功能的完成依据

每项任务明确用户目标、输入输出、授权与副作用、状态归属、资源边界和失败恢复行为。根据实际变更范围验证真实边界，并同步更新配置、接口或运行文档。

已实现、已验证、待验证和拟议能力分别陈述。工具与恢复语义见 [契约与生命周期](contracts-and-lifecycle.md)，记忆机制见 [Memory 与 Context 设计](memory-and-context-design.md)，MCP 操作见 [工具与 MCP](mcp.md)。
